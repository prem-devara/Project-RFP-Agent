RFP Analysis Agent

An AI agent that builds RFP compliance checklists, tested against hand-built answer keys for three public RFPs.

Problem

An RFP can run past 100 pages, with requirements scattered throughout the document. Bid teams build a compliance checklist by hand, and a single missed item can get a proposal rejected.

The build

An agent that reads the RFP and lists every requirement with its category, the page it's on and the exact wording, so each item can be checked against the source. It reads the RFP through a document server that returns the text page by page, so every requirement is tied to the page it came from. The server is built on MCP, so the same RFPs can also be used for Q&A in the Claude desktop app. While writing the proposal, the bid team can ask "What are the insurance limits?" and get an answer with the page it came from.

Code checks the agent's work:

  • Quotes: any quote not found on the page it cites is flagged for review.
  • Page coverage: when the agent says it's done, the code compares the pages it read with the total page count. If any were skipped, it tells the agent which pages are missing and sends it back to read and label them.

Evals

I built the answer keys by hand for four public RFPs. I read each RFP and recorded every requirement in a spreadsheet: what it requires, its section, page, category and exact quote. I followed a written rulebook, for example one requirement per row. For the long RFPs, I labelled selected sections completely. In total, the keys hold about 410 requirements.

One RFP was used to build the agent. The other three were held back for testing, and their answer keys were saved before the agent ever ran on them. A judge AI model compared the agent's checklist with each key, and each test RFP was run three times.

The agent's main weaknesses are cover-page facts and confusing the review process with the scoring criteria. The first version also skipped 55 pages of a 112-page RFP. A page-coverage check fixed that.

What I learned

  • Instructions alone don't guarantee behaviour: the agent was told to read every page and still skipped half of a 112-page RFP. Only a check in code fixed it.
  • The answer keys decide how much the results can be trusted: building them was the hardest part of the project.
  • Results vary between runs: running the agent on the same RFP twice gave precision scores up to 7 points apart. That's why I ran each test three times and reported the average.
