# Labelling rulebook

These rules apply to every RFP answer key (Elysian, Ann Arbor, Kingsport, New York OIG).
The agent's instructions follow the same rules, so the key and the agent split items the same way.

## 1. What to label

Label three kinds of items:

- **Requirements**: what the vendor must do or provide if it wins.
  Signal words: "shall", "must", "will be required to", "is required".
- **Submission instructions**: what the proposal must include, its format, how and when to submit.
- **Evaluation criteria**: how proposals will be scored, including any weights or points.

Do not label:
- "Should" and "may" statements unless the RFP treats them as mandatory.
- Background or description (e.g. "The City currently uses Office 365").
Exception: items listed in a scope of services count as requirements (usually Technical), even when introduced with "may include".

## 2. One obligation per row

- Each separate obligation gets its own row.
  "Provide training and documentation" = two rows.
- A list under one sentence: each item is its own row.
- A requirement with named conditions: split the main item and each condition.
  Example: NGFW firewall + PCI-DSS isolation + MGDPA segregation = three rows.
- Several rows may share the same quote when they come from one sentence.
- A requirement repeated elsewhere in the RFP: label it once, at its first appearance.
- A sentence that introduces a list is not its own row; label only the list items.
Exception: a submission instruction stays as one row, including its deadline, delivery methods and address. A rule about what happens to late or non-compliant submissions is a separate row.


## 3. Types

| Type | Use for |
|---|---|
| Technical | What the system or service must do |
| Submission | What the proposal must include; format, delivery, deadlines, inquiry contact |
| Evaluation | Scoring criteria and weights |
| Legal/Contractual | Terms the vendor must accept or comply with |
| Insurance | Required coverage types and amounts |
| Staffing | Required personnel, roles or qualifications |
| Info | Listed for reference, **not scored** (see below) |

## 4. Info (listed, not scored)

Use Info for items a bid team should see but that are not vendor obligations:
- The agency's own rights (e.g. may cancel the RFP, pays no proposal costs).
- Timeline dates, when the submission deadline is already captured in a Submission row.

Info rows are excluded from recall and precision.

## 5. What to record

| Column | Rule |
|---|---|
| id | Prefix + number in order: E (Elysian), A (Ann Arbor), K (Kingsport), N (New York OIG) |
| requirement | Short description in your own words |
| section | The PDF's heading, as written |
| page | PDF page number |
| type | One of the seven types above |
| quote | Exact text copied from the PDF, never retyped |

## 6. Scope

- The PDF only. Requirements in separate spreadsheets or attachments are out of scope.
- Answer keys are written before the agent is run on that RFP, and never edited afterwards
  to improve a score.
